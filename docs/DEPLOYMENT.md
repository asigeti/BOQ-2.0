# Production Deployment Guide — Fully Free ($0/mo)

**Stack:** Netlify (frontend) + Supabase (database) + Render (backend)

| Service | Tier | Cost | Limits |
|---------|------|------|--------|
| Supabase | Free | $0/mo | 500MB DB, 1GB storage, 50K auth users |
| Render | Free | $0/mo | 750 hours/mo, spins down after 15min idle |
| Netlify | Free | $0/mo | 100GB bandwidth, 300 build min/mo |
| Gemini API | Free | $0/mo | 15 RPM, 1M tokens/day |
| **Total** | | **$0/mo** | |

> **Note:** Render free tier spins down after 15 minutes of inactivity. First request after idle takes ~30-60 seconds (cold start). Subsequent requests are instant.

## Quick Deploy (3 clicks + 2 keys)

### Prerequisites — Get These First

You need exactly **2 things** before deploying:

1. **Supabase DATABASE_URL** (2 minutes):
   - Go to [supabase.com](https://supabase.com) → Sign in with GitHub → New Project
   - Region: `eu-central-1` (closest to Israel)
   - Set a database password → **save it**
   - After creation: **Settings → Database → Connection string → URI**
   - Copy the URI (looks like `postgresql://postgres.[ref]:[password]@aws-0-...pooler.supabase.com:6543/postgres`)

2. **Gemini API Key** (1 minute, free):
   - Go to [aistudio.google.com/apikey](https://aistudio.google.com/apikey)
   - Sign in with Google → Create API Key
   - Copy the key

## Step 1: Deploy Backend to Render (1 click)

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy)

1. Click the button above (or go to [render.com](https://render.com) → New → Web Service → Connect GitHub repo)
2. Render detects `render.yaml` automatically and creates the service
3. Fill in the prompted values:
   - `DATABASE_URL` → paste your Supabase connection string
   - `GEMINI_API_KEY` → paste your Gemini API key
   - `BACKEND_CORS_ORIGINS` → leave empty for now (set after Step 2)
4. Click **Deploy**
5. Wait ~3 minutes. Your backend URL will be: `https://boq-backend.onrender.com`
6. Test: visit `https://YOUR-RENDER-URL/health` → should return `{"status": "healthy"}`

---

## Step 2: Deploy Frontend to Netlify (1 click)

[![Deploy to Netlify](https://www.netlify.com/img/deploy/button.svg)](https://app.netlify.com/start)

1. Click the button above (or go to [netlify.com](https://netlify.com) → Add new site → Import from Git)
2. Connect your GitHub repo
3. Netlify reads `frontend/netlify.toml` automatically — no config needed
4. Go to **Site settings → Environment variables** and add:

| Variable | Value |
|----------|-------|
| `NEXT_PUBLIC_API_URL` | `https://YOUR-RENDER-URL.onrender.com` (from Step 1) |

5. Trigger a redeploy: **Deploys → Trigger deploy → Deploy site**
6. Your site is live at `https://YOUR-SITE.netlify.app`

---

## Step 3: Connect CORS (30 seconds)

Now that you have the Netlify URL, go back to Render:

1. Open your backend service → **Environment**
2. Set `BACKEND_CORS_ORIGINS` to: `https://YOUR-SITE.netlify.app`
3. Render auto-redeploys

**Done.** Your app is live and fully free.

4. Upload a PDF or DXF file

## CLI Deploy (Alternative — No Browser Needed)

If you have the CLIs installed, you can deploy entirely from the terminal:

```bash
# Install CLIs (one-time)
npm install -g netlify-cli
pip install render-cli

# Deploy backend
render deploy --service boq-backend

# Deploy frontend
cd frontend
netlify deploy --prod
```

## Auto-Deploy (CI/CD)

Both Render and Netlify auto-deploy when you push to GitHub:

- **Push to `main`** → Both services rebuild and redeploy automatically
- **GitHub Actions CI** runs on every push (`.github/workflows/ci.yml`) — validates backend compiles and frontend builds

No manual deploys needed after initial setup.

## Free Tier Limits & Workarounds

### Render Free Tier
- **Cold starts**: Backend sleeps after 15min idle. First request takes ~30-60s to wake up.
  - **Workaround**: Use [UptimeRobot](https://uptimerobot.com) (free) to ping `/health` every 14 minutes and keep it awake.
- **750 hours/month**: Enough for 1 service running 24/7 (720 hours in a 30-day month).
- **512MB RAM**: Sufficient for this backend. If you hit limits, optimize imports.

### Supabase Free Tier
- **500MB database**: Plenty for BOQ data. Monitor at Dashboard → Database → Database size.
- **50K monthly active users**: More than enough.
- **1GB file storage**: If needed, enable Supabase Storage for persistent file uploads.

### Netlify Free Tier
- **100GB bandwidth**: More than enough for a business tool.
- **300 build minutes/month**: ~60 deploys (5 min each).

### Gemini API Free Tier
- **15 requests per minute**: Sufficient for single-user extraction.
- **1 million tokens per day**: ~200 PDF extractions per day.
- **Rate limited, not capped**: Requests queue, never incur charges.

## Known Limitations

- **DWG files**: AutoCAD COM not available on Linux. Uses ezdxf fallback (less accurate)
- **File uploads**: Stored on Render's ephemeral filesystem — files lost on redeploy. For persistent storage, use Supabase Storage
- **Redis**: Not included. Caching features won't work on free tier
- **Cold starts**: ~30-60s delay after 15min idle (use UptimeRobot to avoid)

## Troubleshooting

**Backend won't start on Render:**
- Check Render logs (Dashboard → Logs)
- Verify `DATABASE_URL` is correct — copy fresh from Supabase
- Make sure the Dockerfile is detected (render.yaml points to `./backend/Dockerfile`)

**Frontend can't reach backend:**
- Check `NEXT_PUBLIC_API_URL` is set correctly in Netlify env vars
- **Redeploy frontend** after setting the env var (Next.js bakes env vars at build time)
- Check `BACKEND_CORS_ORIGINS` includes your exact Netlify domain

**Database connection fails:**
- Supabase uses port `6543` (pooler) or `5432` (direct) — use the **pooler URL**
- `ENVIRONMENT=production` enables `sslmode=require` automatically in the backend

**Render deploy fails with "Dockerfile not found":**
- The `render.yaml` sets `dockerfilePath: ./backend/Dockerfile` and `dockerContext: ./backend`
- Make sure `render.yaml` is committed and pushed to GitHub

**Cold start too slow:**
- Sign up at [uptimerobot.com](https://uptimerobot.com) (free)
- Add HTTP monitor: `https://YOUR-RENDER-URL.onrender.com/health`
- Set interval to 5 minutes
- This keeps the backend warm 24/7 at zero cost
