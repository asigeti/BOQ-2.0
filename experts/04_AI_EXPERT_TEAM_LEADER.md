## AI/ML PROJECT PATTERNS & ANTI-PATTERNS

### Success Patterns

✅ **Start Simple**
- Baseline model first (linear, simple neural net)
- Establish performance floor
- Understand data before complex models
- Iterate from there

✅ **Data Quality Over Quantity**
- 1000 high-quality labeled examples > 1M noisy ones
- Invest in data cleaning and validation
- Human-in-the-loop for quality
- Regular data audits

✅ **Measure What Matters**
- Business metrics, not just model metrics
- Real-world performance, not test set only
- Latency, cost, and accuracy together
- User satisfaction metrics

✅ **Gradual Rollout**
- Shadow mode first (no user impact)
- Small percentage rollout
- A/B test against baseline
- Monitor closely, rollback easily

✅ **Cross-Functional Alignment**
- Product defines success criteria
- Design considers AI limitations
- Engineering plans for scale
- Legal reviews compliance
- Regular syncs throughout

### Anti-Patterns

❌ **Resume-Driven Development**
- Using latest technique because it's trendy
- Not considering if it solves the problem
- Complexity for complexity's sake
- ✅ Instead: Choose simplest approach that works

❌ **Data Debt**
- No data versioning
- Unclear data provenance
- Schema evolution without documentation
- No data quality monitoring
- ✅ Instead: Treat data as first-class artifact

❌ **Notebook Hell**
- Production code in Jupyter notebooks
- No version control
- Can't reproduce results
- Spaghetti dependencies
- ✅ Instead: Notebooks for exploration, modules for production

❌ **Optimization Obsession**
- Premature optimization
- Tuning model endlessly for marginal gains
- Ignoring business impact
- ✅ Instead: Optimize only bottlenecks, measure impact

❌ **Black Box Deployment**
- No monitoring in production
- No understanding of failures
- No graceful degradation
- ✅ Instead: Comprehensive monitoring and fallbacks

❌ **The Perfect Dataset Myth**
- Waiting for "enough" data
- Waiting for "clean" data
- Never starting because data isn't perfect
- ✅ Instead: Start with what you have, iterate

## CRISIS MANAGEMENT IN AI/ML

### Production Model Failure

**Immediate Response:**
1. **Rollback** to previous version (if performance degraded)
2. **Assess impact** (how many users affected?)
3. **Communicate** to stakeholders (what happened, ETA for fix)
4. **Assemble team** (on-call + relevant experts)

**Investigation:**
- Check data pipeline (data drift?)
- Check model metrics (accuracy, latency)
- Review recent changes
- Analyze error logs
- Compare with baseline

**Resolution:**
- Fix root cause
- Test thoroughly
- Gradual re-deployment
- Enhanced monitoring

**Post-Mortem:**
- What happened and why?
- What went well in response?
- What could be better?
- Action items to prevent recurrence
- Blameless analysis

### Ethical Issues Discovered

**If Bias or Harm Identified:**
1. **Immediate**: Disable model if causing active harm
2. **Assess**: Scope and severity of issue
3. **Communicate**: Transparently to leadership and affected users
4. **Fix**: Address root cause (often training data)
5. **Audit**: Comprehensive review of all models
6. **Prevent**: Improve processes to catch earlier

### Team Member Sudden Departure

**Immediate:**
- Document knowledge before they leave
- Reassign critical responsibilities
- Identify dependencies
- Plan for coverage

**Short-term:**
- Redistribute work temporarily
- Accelerate hiring if needed
- Engage contractors if urgent
- Cross-train remaining team

**Long-term:**
- Hire replacement (or decide not to)
- Document tribal knowledge
- Reduce single points of failure
- Build redundancy
